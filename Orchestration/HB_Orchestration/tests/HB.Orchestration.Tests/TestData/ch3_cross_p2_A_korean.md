| B-05 / A2-05 | REVISED | **중간, 사양 의존.** 초기화가 없다는 것은 추론이 아니라 코드상 사실이다. 프레임별 집계라면 결함이지만 누적 집계라면 초기화가 오히려 사양 변경이다. 원본에는 경쟁도 있으므로 정확한 배수 증가가 보장되지 않는다. 프레임별 집계라면 초기화 또는 출력 덮어쓰기로 수정한다. | 먼저 경쟁을 제거하고 입력을 고정한다. 프레임별 사양이면 매 프레임 전체 합이 `count`, 누적 사양이면 완료한 집계 횟수에 따른 합인지 확인한다. |

## 2. 상대 수정안 검토 — 새로 생기는 문제 / 범위 초과 여부

- **A2-07 / B-01 — 원자 증가 방식**
  - **판정:** 유효한 대안이다. 정상 범위의 정수 집계에서는 원자 증가로 갱신 유실을 막을 수 있다. 병렬 처리 유지라는 제약에도 맞는다.
  - **새 위험 / 심각도 중간:** 원시 포인터 접근은 인덱서의 요소별 범위 검사를 우회한다. 위치가 유한한 값이라는 전제가 깨지면 셀 계산과 포인터 접근의 안전성을 별도로 보장해야 한다. 제공된 초기화와 0인 속도만으로는 이 경로가 발생하지 않는다.
  - **대응:** 유효한 위치·셀 범위를 명시하고, 외부 위치 갱신이 있다면 입력을 검증한다. 안전성 검사 전체를 끄는 방식으로 확대하지 않는다.
  - **성능 미확인:** 초기 x 범위가 좁아 소수 셀에 원자 연산이 집중된다. 이것이 성능 실패라는 근거는 없지만, 청크별 히스토그램보다 빠르다고도 단정할 수 없다.
  - **검증:** 고정 입력으로 전체 셀 정확성을 확인한 뒤, 20,000개 및 단일 셀 집중 조건에서 두 방식을 프로파일링한다. **자료 부족: Burst·Collections 버전 및 대상 플랫폼별 컴파일 결과.**
  - **범위 초과:** 없음.

- **A2-08 / B-01 — unsafe 설정 안내**
  - **새 문제 / 심각도 낮음:** `UnsafeUtility.AddressOf`로 바꾸는 것만으로 unsafe 코드 허용 설정이 불필요해지지는 않는다. 포인터를 사용하는 제시 방식에는 해당 설정이 필요하다.
  - **대응:** unsafe 허용을 명시하거나, 포인터를 사용하지 않는 청크별 집계 방식을 선택한다.
  - **검증:** unsafe 허용을 끈 상태와 켠 상태에서 각각 컴파일한다.
  - **범위 초과:** 프로젝트 설정 변경은 구현 선택의 부수 조건이며, 필수 해결책은 아니다.

- **A2-09 / B-02·B-03·B-06 — 종료 처리의 핸들 누락**
  - **새 문제라기보다 잔존 결함 / 심각도 높음:** 첫 예약 성공 후 두 번째 예약이 실패하면 원본 `_handle`은 첫 작업을 대표하지 않는다. 따라서 제안한 종료 처리만으로는 모든 작업의 완료를 보장하지 못한다.
  - **대응:** 예약 성공 직후마다 `_handle`에 저장하고, 다음 작업을 그 핸들에 연결한다. `Complete()` 실패 시 무조건 해제로 진행하지 않는다. **자료 부족: Job 실패 후 중단·복구 정책.**
  - **검증:** 첫 예약 직후 예외를 주입하고 종료 시 해당 작업을 기다리는지 확인한다.
  - **범위 초과:** 없음.

- **A2-10 / B-04 — 초기 위치 분포 변경**
  - **새 문제 / 심각도 중간:** 방향에 균등한 반지름을 곱하면 원래의 구 내부 균일 분포와 달리 중심 쪽 밀도가 높아진다. 고정 시드 도입에 불필요한 입력 분포 변경이다.
  - **대응:** 구 내부 균일 분포를 유지하려면 반지름을 `50f * math.pow(rng.NextFloat(), 1f / 3f)`로 생성한다. 정확한 기존 표본 재현이 필요하면 초기 위치를 저장·재사용한다.
  - **검증:** 반지름이 `r` 이하인 표본 비율이 대략 `(r / 50)^3`인지 확인한다.
  - **범위 초과:** 별도 동의 없는 분포 변경은 요청 범위 밖이다.

- **A2-11 / B-05 — 메인 스레드 초기화**
  - **조건부 위험 / 심각도 높음:** 이전 작업이 완료된 정상 경로에서는 작은 배열의 메인 스레드 초기화 자체가 병렬 처리 제약 위반은 아니다. 그러나 완료가 누락된 경로에서 실행하면 진행 중인 집계와 충돌할 수 있다. 새 프레임의 Job에 의존성을 넣어도 그보다 앞선 메인 스레드 쓰기는 보호되지 않는다.
  - **대응:** 초기화 전 소유권 반환을 보장하거나, 초기화 Job을 이전 핸들에 연결한다. 출력 셀을 덮어쓰는 합산 방식도 대안이다. 누적 사양이면 이 변경은 적용하지 않는다.
  - **검증:** 이전 프레임의 완료를 테스트용으로 지연시킨 상태에서 안전성 오류와 결과 손상이 없는지 확인한다.
  - **범위 초과:** 프레임별 집계로 확정되지 않은 상태에서 무조건 초기화하면 사양 변경이다.

## 3. 내 Phase 1 수정 — 철회·수정한 항목과 이유

- **A2-12 / A-03 및 수정 방향 3-1**
  - 기본 예제에서 구 표면에만 위치를 생성하도록 바꾼 것은 불필요한 분포 변경이었다. 이를 인정하고 철회한다. 후속 선택지로 제시했던 구 내부 균일 분포 식을 기본안으로 올린다.
  - **심각도:** 중간.
  - **검증:** A2-10의 반지름 분포 검증과 동일 입력 반복 검증을 함께 수행한다.

- **A2-13 / A-05 및 수정 방향 3-1·3-4**
  - 생성 여부 확인은 종료 시 부분 할당을 다루지만, `Start()`에서 검증·할당이 실패한 뒤 후속 `Update()`가 실행되는 경로까지 해결하지는 못한다. 기존 수정안은 이 부분에서 불완전했다.
  - **심각도:** 중간.
  - **대응:** 초기화 성공 상태를 두고 성공한 경우에만 `Update()`·`LateUpdate()`를 실행한다. 초기화 실패 시 생성된 배열을 정리하고 컴포넌트를 비활성화하는 방식도 가능하다.
  - **검증:** `count <= 0`과 각 할당 직후의 테스트용 예외를 주입하여 추가 예약·배열 접근·누수가 없는지 확인한다.

## 4. 미해결 쟁점 — 실행이나 사양 결정이 있어야 닫히는 것

- **A2-14 / 실제 증상 대응:** 자료 부족: 에디터·종료 오류 전문, 스택, 패키지 버전, 빌드 안전성 설정. 확인된 결함과 각각의 관찰된 예외를 일대일로 연결할 수 없다.
- **A2-15 / 집계 사양:** 프레임별인지 누적인지, 이동 전·후 어느 위치를 집계할지 미정이다. 누적이면 초기화 대신 정수 범위와 초기화 시점도 결정해야 한다.
- **A2-16 / 결정성 범위:** 동일 입력의 정수 집계는 두 수정 방식으로 해결 가능하다. 실행 간 입력 재현, 시간 입력 재현, CPU·Burst 설정 간 이동 결과의 비트 동일성은 별도 요구다.
- **A2-17 / 구현 선택:** 원자 증가와 청크별 집계의 실제 성능 및 대상 플랫폼 컴파일 결과는 미확인이다. 성능 측정 없이 하나를 필수안으로 확정하지 않는다.
