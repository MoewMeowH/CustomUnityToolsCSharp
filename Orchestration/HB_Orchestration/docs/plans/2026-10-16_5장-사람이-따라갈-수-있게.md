# 5장 — 사람이 따라갈 수 있게 만들기 (기록 보강 · 판단 근거 · 세션 기록 · 나란히 보기)

## 요약

- A: 호출 기록에 `Provenance`를 추가한다. 실제로 보낸 시스템 프롬프트, 리뷰 지침 파일, modes.json, 서버 설정의 SHA-256을 남기고, 원문은 해시 이름으로 한 번만 저장한다. 서버 설정은 해시만 남긴다 (권장).
- B: `run_mode`에 `reason`(모든 모드 필수)과 `ownReview`(modes.json `RequireOwnReview: true`인 모드만 필수)를 추가한다. 두 값은 에이전트에게 보내지 않고 기록에만 남긴다.
- C·D: 대시보드에 Claude Code 세션 기록 화면(지침 목록 + run_mode 연결, 읽기 전용, 대화 본문 없음)을 추가하고, 호출 상세 화면에 판단과 응답을 나란히 보여 준다. 해시와 세션 링크도 함께 보여 준다.

## 배경

지시서의 배경 표(지휘자가 무엇을 알았나 / 왜 판단했나 / 에이전트가 무엇을 받았나)를 그대로 따른다. 이번 조사에서 확인한 사실은 다음과 같다.

**코드 (확정)**
- 시스템 프롬프트는 `ModeRunner.RunAsync`에서 `역할 프롬프트 + Prompts.CommonRules + (UseGuidelines ? 지침 : "")`으로 만든다 (`ModeRunner.cs:79`). Debate 토론자는 여기에 `Prompts.DebateRules`가 더 붙는다 (`ModeRunner.cs:197`). MAF에 실제로 넘기는 문자열은 `AgentRunner.RunAttemptAsync`의 `call.Instructions`(`AgentRunner.cs:134`) 하나다.
- `GuidelinesLoader.Load`는 경로를 돌려주지 않는다. `File.ReadAllText`로 읽은 본문 앞에 `"\n\n## 프로젝트 지침\n"`을 붙인 문자열만 돌려준다. 파일이 없으면 `""`를 돌려준다.
- `ModeStore.Load`는 modes.json을 호출마다 텍스트로 읽는다. 서버 설정은 `OrchestrationSource.SettingsPath`(= dll 옆 `appsettings.json`)에 있고, `AgentCatalog`가 바뀔 때 다시 읽는다. 다시 읽기에 실패하면 이전 값으로 동작한다 (`catalog.ReloadError`).
- `CallRecord`는 시도마다 한 줄이다. `ContextRoots`는 `[JsonIgnore(WhenWritingNull)]`로 쓰지 않은 호출에서 생략한다 (4장 결정).
- 대시보드 `/Sessions`는 **살아 있는 MCP 서버 프로세스(pid)** 화면이다. Claude Code 세션 기록과는 다른 개념이므로 C는 별도 화면으로 만든다.
- 대시보드의 modes.json 편집은 JsonNode로 모르는 키를 보존한다 (`ModesConfigService.cs:77`). 따라서 `RequireOwnReview`를 추가해도 편집 시 사라지지 않는다.
- 대시보드는 `http://localhost:5280`에 바인딩된다 (`appsettings.json`).

## 계획

### A. 호출 기록 보강

**기록 필드** — `CallRecord`에 객체 하나를 추가한다.

```
Provenance (CallProvenance?, 예전 기록은 null → 대시보드 "기록 없음")
  InstructionsSha256, InstructionsBytes      ← call.Instructions의 UTF-8(BOM 없음) 바이트
  Guidelines { Attached, Path?, Sha256?, Bytes?, Reason? }
      Attached=false면 Reason: "역할 UseGuidelines=false" | "지침 파일 없음"
  Modes     { Path, Sha256 }                 ← 실행 시점 modes.json 원본 바이트
  Settings  { Path, Sha256, Stored, SecretScan, ReloadError? }
  StoreErrors [ ... ]                        ← 원문 저장 실패. 없으면 필드 생략
```

**해시 계산 위치 (답 1)**
- 시스템 프롬프트는 `AgentRunner.RunAttemptAsync`에서 `ChatClientAgent`에 넘기는 `call.Instructions`를 그대로 해시한다. Debate의 `DebateRules`까지 붙은 최종 문자열이다. `ModeRunner`에서 미리 계산하지 않는다 (Debate에서 어긋남).
- 지침 파일은 원본 파일 바이트를 해시한다 (`sha256sum`과 대조 가능). `GuidelinesLoader`가 파일을 **바이트로 한 번만 읽고** 그 바이트를 디코딩해 본문을 만든다. 해시한 내용과 보낸 내용이 다른 시점의 파일이 되는 경합을 막는다. 디코딩은 지금 `ReadAllText`와 같게 BOM을 감지한다.
- modes.json도 `ModeStore.Load`가 바이트로 한 번 읽어 해시하고, 같은 바이트로 역직렬화한다.
- 서버 설정은 run 시작 때 `SettingsPath`를 바이트로 읽어 해시한다. `catalog.ReloadError`가 있으면 함께 기록한다 (파일과 실제 적용 값이 다를 수 있다는 표시).
- 한 run 안의 모든 단계·시도는 같은 Modes/Settings/Guidelines 값을 쓴다. Instructions는 단계마다 다르다.

**원문 저장 위치 (답 1)**
- `<calls.jsonl 폴더>/blobs/<sha256>.txt`에 둔다. 기본은 `%LOCALAPPDATA%\HB_Orchestration\blobs\`이다.
  - 설정 `Orchestration:Records:BlobFolder`로 바꿀 수 있다. 비우면 위 기본 경로를 쓴다.
- 대상은 시스템 프롬프트(보낸 문자열의 UTF-8 바이트), 지침 파일 원본 바이트, modes.json 원본 바이트다.
- 이미 있으면 쓰지 않는다. 쓸 때는 `<sha>.tmp-<pid>`에 쓰고 `File.Move(overwrite:false)`로 옮긴다. 다른 MCP 프로세스가 먼저 만들어 이동이 실패하면 성공으로 본다 (내용 주소라 같은 내용).
- 실패하면 로그 경고를 남기고 `StoreErrors`에 `"instructions: UnauthorizedAccessException …"`처럼 한 줄씩 넣는다. 호출은 그대로 진행한다. 해시 계산 자체도 try로 감싸고, 실패하면 해당 값은 null에 `StoreErrors`로 남긴다.

**서버 설정 원문 (답 1) — 권장: 해시만**
- 지금은 키 검사가 0건이지만, 대시보드 편집이나 사람의 실수로 값이 들어올 수 있다. 원문이 blobs에 남으면 지우기 전까지 계속 남는다.
- `Settings.Stored=false`, `SecretScan`에 `"통과"` 또는 `"의심 n건"`을 기록한다. 검사 결과는 원문을 남기지 않을 때도 기록한다.
- 선택 설정 `Orchestration:Records:StoreSettingsText`(기본 false)를 둔다. true여도 키 검사에 걸리면 저장하지 않고 `StoreErrors`에 사유를 남긴다.
- 해시만 남겨도 "이 호출의 설정이 지금 파일과 같은가"는 확정할 수 있다. 다른 경우의 차이는 git(`src/…/appsettings.json`)과 대시보드 편집 이력으로 추적한다.

**필드를 항상 넣을지 (답 2)** — `Provenance`는 **항상** 넣는다.
- `ContextRoots`는 "추가 루트를 쓴 호출에만" 생기는 정보라 생략했다. Provenance는 모든 호출에 해당하므로 같은 기준을 적용하면 항상 넣는 것이 맞다.
- 지침을 붙이지 않은 경우도 "붙이지 않았다는 사실"이 요구사항이다. 그래서 `Attached:false` + `Reason`을 쓴다.
- 생략은 `StoreErrors`(실패가 없을 때)에만 한다. 예전 기록에는 `Provenance`가 null이므로 "기록 없음"과 "붙이지 않음"이 구분된다.

### B. `run_mode` 기록용 인자

- `ModeTools.RunMode`에 `string? reason = null`, `string? ownReview = null`을 추가한다.
  - nullable로 두는 이유: 필수 스키마로 두면 SDK 바인딩 단계에서 실패해 `[`로 시작하는 문자열이 아닌 도구 오류가 나간다.
  - 필수 여부는 `ModeRunner`에서 검사한다.
- **review 계열 지정 (답 3):** `ModeDefinition.RequireOwnReview`(bool, 기본 false)를 추가한다. 키가 없으면 필수가 아니다. 기본 modes.json(src·publish 동일)에서 true로 둘 후보는 `review`, `panel`, `cross_p1`, `cross_p1_guided`다 → 사용자에게 물을 것 2.
  - `list_modes`에서 해당 모드 줄 끝에 ` [ownReview 필수]`를 붙인다. 지휘자가 거절을 겪기 전에 알 수 있게 한다.
- **검사 위치:** 모드를 찾은 직후, Steps 검사 다음이다. `TryReserve`(실행 횟수 차감)보다 앞이고, 첨부 읽기·예산 확인보다도 앞이다. 공백만 있으면 없는 것으로 본다.
  - 거절 문구 예: `[reason 필요] 이 모드를 부른 이유를 reason에 한 줄로 넣어 다시 호출하세요. (실행 횟수 차감 없음)`
- **인자 설명 문구 (짧게, 답 3):**
  - `reason`: `"이 모드를 부른 이유 한 줄. 필수. 기록용이며 에이전트에게 전달되지 않음."`
  - `ownReview`: `"결과를 보기 전에 완성한 자체 검토 원문. [ownReview 필수] 모드에서 필수. 기록용이며 에이전트에게 전달되지 않음."`
- **길이 제한 (답 3):** `Orchestration:Records:MaxReasonChars`(기본 500), `MaxOwnReviewChars`(기본 30,000)를 둔다. 0이면 무제한이다. 넘으면 잘라 쓰지 않고 `[`로 거절하며 횟수를 차감하지 않는다 (잘라서 남기면 "원문 그대로" 기준이 깨진다).
- **기록 단위 (답 4): 그 run의 모든 기록 줄(단계·시도마다)에 같은 값을 넣는다.**
  - 한 번만 넣을 "첫 줄"이 흐름마다 다르다 (Concurrent는 동시 시작, 1단계 실패, 재시도 줄). 그래서 줄마다 자기 완결적으로 둔다.
  - 중복 비용: 같은 줄의 `Prompt`가 이미 단계마다 input 전체(최대 100,000자)를 중복 저장하므로 상대적으로 작다.
  - 대안 `runs.jsonl`(run 단위 별도 파일)은 "calls.jsonl만으로" 원칙에서 벗어나 버렸다.
- **독립성:** 두 값은 `CallMeta`로만 흐른다. `BuildPrompt`·`BuildDebatePrompt`·Instructions 조립에는 전달되지 않는다. 테스트로 보증한다 (아래).
- **규칙서:** `project-files/CLAUDE.md`의 "언제 부르나" 또는 "input 작성" 절에 한 항목을 추가한다.
  - 문구 초안: "`run_mode`에는 `reason`(부른 이유 한 줄)을 항상 넣는다. `[ownReview 필수]` 모드에는 결과를 보기 전에 완성한 너의 리뷰 원문을 `ownReview`로 넣는다. 둘 다 에이전트에게 가지 않고 기록에만 남는다."
  - `tools/Sync-ProjectFiles.ps1 -Apply`로 Unity 쪽에 복사하고 SHA-256을 대조한다. `.claude/commands/cross-review.md`·`mode.md`에 run_mode 호출 예가 있으면 같이 고친다.

### C. 대시보드 — Claude Code 세션 기록

- **새 화면** `/ClaudeSessions`(목록)와 `/ClaudeSession?id=…`(상세)를 만든다. 기존 `/Sessions`(MCP 프로세스)와 이름을 구분하고, 메뉴 이름은 "Claude 세션"으로 한다.
- **위치·경로 인코딩 (답 5):**
  - 설정 `Dashboard:ClaudeProjectsDir`를 둔다. 비우면 `CLAUDE_CONFIG_DIR` 환경 변수의 `projects`, 없으면 `%USERPROFILE%\.claude\projects`를 쓴다 (`CLAUDE_CONFIG_DIR` 지원은 추정).
  - 인코딩은 되돌릴 수 없으므로 폴더 이름을 해석하지 않는다. 세션의 프로젝트는 각 줄의 `cwd`로 정한다.
  - calls.jsonl `ProjectDir`로 폴더를 찾아야 할 때만 "영숫자 외 → `-`" 규칙으로 인코딩해 비교한다 (위 두 예로 확인).
- **읽기:**
  - 최상위의 `<GUID>.jsonl`만 대상이다. `*.orphaned-*.jsonl`과 하위 폴더는 목록에서 뺀다.
  - `FileShare.ReadWrite`로 열고 `new UTF8Encoding(false, throwOnInvalidBytes:false)`로 **명시**한다. `StreamReader.ReadLine`으로 줄 단위로 읽는다.
  - 줄마다 `JsonDocument`로 파싱하는데, 필요한 줄만 파싱한다 (문자열 사전 검사: `"instructions"`, `run_mode`, `tool_result`, `task-notification`).
  - 결과는 (경로, 크기, 수정 시각) 키로 메모리 캐시한다.
  - 목록은 수정 시각 최근 N개(`Dashboard:ClaudeSessionLimit`, 기본 50)로 제한한다.
- **세션 목록:** 시작 시각(첫 `timestamp`를 로컬 시각으로), `version`, `cwd`, 세션 ID 앞 8자, 지침 파일 수, 연결된 run 수.
- **세션 상세:**
  - 모든 `instructions` 항목(여러 번 있을 수 있음)을 시각 순으로 보여 준다. 열은 `files[].path`, `type`, 크기, SHA-256, 원본 대조다.
    - 크기·SHA-256은 `content` 문자열의 UTF-8 바이트 기준이다.
    - 원본 대조는 지금 디스크 파일과 비교해 `같음` / `끝 줄바꿈만 다름` / `다름(이후 변경)` / `파일 없음` 중 하나를 표시한다. 디스크 쪽 기준은 위 조사로 확인한 정규화(끝 줄바꿈 1개)다 → 사용자에게 물을 것 4.
  - 판정은 `files[].path`로만 한다. 본문(content)은 보여 주지 않는다.
- **run_mode 연결 (답 5):**
  1. **확정:** 이름이 `__run_mode`로 끝나는 tool_use를 찾는다. 서버 이름이 바뀌어도 되도록 접미사로 본다. 그 결과 텍스트의 첫 줄 `runId: <10자 hex>`로 연결한다. 결과 텍스트는 같은 `tool_use_id`의 tool_result이고, 백그라운드로 넘어갔으면 그 task id의 `<task-notification>`이며, persisted면 미리보기다.
  2. **추정:** 머리말이 없으면(3장 이전 기록, 실패 문구) calls.jsonl에서 다음 조건을 모두 만족하는 run을 찾는다. 후보가 정확히 하나일 때만 "추정(시각·모드)"으로 연결한다. 둘 이상이면 "후보 n개"로만 표시한다.
     - Mode가 tool_use `input.mode`와 같다 (대소문자 무시).
     - ProjectDir이 세션 `cwd`와 같다.
     - run의 가장 이른 기록 시각이 tool_use 시각 −2초 ~ +60초 안이다.
     - 아직 확정 연결되지 않은 run이다.
  - 화면에는 tool_use 시각, 모드, runId, 확정/추정만 보여 준다. `input`·`reason`·결과 본문은 보여 주지 않는다 ("대화 본문은 보여 주지 않는다").
- **알 수 없는 형식:**
  - JSON이 아닌 줄과 필요한 필드 타입이 다른 줄은 세지 않고 건너뛴다. 세션 상세에 "알 수 없는 줄 n개"로 표시한다.
  - `sessionId`·`timestamp`를 하나도 찾지 못한 파일, 또는 읽기 예외가 난 파일은 목록에 "알 수 없는 형식"으로 표시한다. 예외는 화면 밖으로 내보내지 않는다.
- **읽기 전용:** 쓰기 API를 쓰지 않는다. 테스트에서 읽기 전후 파일의 크기·수정 시각·해시가 같은지 확인한다.

### D. 호출 상세에서 나란히 보기

- `Call` 화면 위쪽에 3열을 둔다: 지휘자 `reason` / 지휘자 `ownReview` / 에이전트 응답. 좁은 화면에서는 세로로 쌓는다. `ownReview`는 응답과 같은 Markdig 파이프라인(`DisableHtml`)으로 렌더링한다. 값이 없으면 "기록 없음"(예전 기록)으로, 해당 없는 모드면 "해당 없음"으로 표시한다. `ownReview`가 비었고 그 모드가 필수가 아니었던 경우다.
- Provenance 표에는 각 항목의 경로·SHA-256 앞 12자(전체는 title)·크기·저장 여부·저장 오류를 둔다.

  - 같은 run의 다른 단계와 Instructions 해시가 다르면 단계 목록에 함께 보여 준다.
- C의 색인(runId → 세션)으로 "세션 90430e3d (확정)" 링크를 단다. 없으면 "연결된 세션 없음"으로 표시한다.

## 위험

- **세션 기록 형식은 비공식이다.** 바뀌면 C가 "알 수 없는 형식"이나 연결 없음으로 보인다. 화면은 깨지지 않게 한다. 형식 의존 코드는 한 클래스(`ClaudeTranscriptReader`)에 모은다.
- **"실제로 보낸" 바이트의 범위:** 해시는 MAF에 넘긴 Instructions 문자열 기준이다. MAF/SDK가 그 문자열을 시스템 메시지(또는 `ChatOptions.Instructions`)로 바꿔 보내는 과정에서 내용이 바뀌지 않는다고 본다 (추정). IChatClient 경계에서 받은 값과 바이트가 같은지는 테스트로 확인한다 (확정 범위는 IChatClient까지).
- **설정 파일 해시 ≠ 실제 적용 값:** 환경 변수(`Orchestration__…`)나 `appsettings.{Environment}.json`이 덮어쓴 값은 해시에 잡히지 않는다. 다시 읽기 실패로 이전 값이 적용 중인 경우는 `ReloadError`로 표시한다.
- **blobs 증가:** 역할 × 지침 버전 × modes.json 편집 수만큼 생긴다. 하나에 수 KB라 당분간 정리 기능은 만들지 않는다.
- **`ownReview`에 민감 내용:** 기록에 평문으로 남는다. 이미 Prompt에 코드가 평문으로 남는 것과 같은 수준이다. 대시보드는 localhost 바인딩이다.
- **추정 연결 오판:** 같은 프로젝트에서 같은 모드를 두 세션이 거의 동시에 부르면 후보가 둘이 된다. 이때는 연결하지 않고 "후보 n개"로 표시한다.
- **테스트 데이터:** 실제 세션 기록에는 대화 전체가 있으므로 TestData에 커밋하지 않는다. 테스트는 합성한 jsonl로 하고, 실제 세션 확인은 로컬에서만 하고 결과(해시·개수)만 로그에 남긴다.

>    이 규칙은 파일 3개로 확인한 관찰이라 작업 로그에 추정 범위로 기록할 것.

이 답으로 바뀐 계획 항목:

- C 원본 대조: 판정 값은 `같음` / `끝 줄바꿈만 다름` / `다름` / `파일 없음` 넷이다. `끝 줄바꿈만 다름`은 "디스크 바이트 = content UTF-8 바이트 + `0x0A` 정확히 1개"일 때만 쓴다. CRLF나 줄바꿈 2개 이상 등 그 밖의 차이는 모두 `다름`이다 (계획 본문의 `다름(이후 변경)`은 `다름`으로 통일한다). 이 규칙은 파일 3개(`90430e3d`)로 확인한 관찰이므로 작업 로그에 추정 범위로 적는다.
